# Project Structure

`create-web` scaffolds three project types. **App** and **Documentation site** share
the same routing layout; **Library** is a flat package for publishable components.

## App

A new app looks like this:

```text
my-app/
├─ app/
│  ├─ page.jsx        # route: /
│  ├─ layout.jsx      # shared layout wrapping all routes
│  ├─ 404.jsx         # not-found page
│  ├─ about/
│  │  └─ page.jsx     # route: /about
│  ├─ api/
│  │  └─ hello/
│  │     └─ route.js  # API endpoint: GET /api/hello
│  └─ global.css
├─ index.html         # mount point + injected bundle
└─ package.json
```

## Documentation site

Docs projects add an `otfw.config.js` and an `app/docs/` section for MDX content:

```text
my-docs/
├─ app/
│  ├─ page.jsx            # marketing landing page
│  ├─ layout.jsx
│  ├─ docs/
│  │  ├─ layout.jsx       # docs shell (sidebar + TOC)
│  │  ├─ _meta.js         # sidebar order
│  │  └─ page.mdx         # /docs introduction
│  └─ global.css
├─ otfw.config.js         # @opentf/web-docs config
├─ index.html
└─ package.json
```

## Library

Library projects export source components from the package root — no `app/` folder:

```text
my-lib/
├─ index.js           # package entry
├─ src/
│  └─ Counter.jsx
├─ tests/
│  └─ counter.test.js
├─ test-setup.js
├─ bunfig.toml
└─ package.json
```

See [Library template](/docs/getting-started/library-template) for publish and
consumption details.

## Special files (App & Docs)

| File | Role |
| --- | --- |
| `page.jsx` | A route. The folder path is the URL (`app/about/page.jsx` → `/about`). |
| `layout.jsx` | Wraps every route below it; nests with the folder tree. |
| `404.jsx` | Rendered when no route matches. |
| `route.js` | An [API endpoint](/docs/routing/api-routes). The folder is the URL (`app/api/hello/route.js` → `/api/hello`); a folder holds a `page.*` or a `route.*`, never both. |
| `_middleware.js` | [Request middleware](/docs/routing/middleware) for its folder and everything nested under it (pages, API, loader data, SSR). |
| `index.html` | The HTML shell. The toolchain mounts the app into `#app` and injects the bundle. |
| `otfw.config.js` | Docs-site configuration (`@opentf/web-docs`). Present in Docs projects only. |

Every other PascalCase `.jsx`/`.tsx` file is a reusable component — no registration
needed (see [Components](/docs/core-concepts/components)).

## Conventions

- `.jsx`/`.tsx` files must have a default export.
- Components are PascalCase (`UserCard.jsx`).
- You never import `$state`, `onMount`, etc. — the compiler injects them.

<Callout type="info" title="TypeScript">
  Choose TypeScript at the scaffold prompt to get `.tsx` pages, `.ts` API routes,
  `tsconfig.json`, and macro typings (`app/otfw-env.d.ts`). Docs sites keep
  `otfw.config.js` and `_meta.js` as JavaScript — the toolchain reads those today.
</Callout>
