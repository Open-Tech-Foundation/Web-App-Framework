# Introduction

OTF Web compiles your JSX directly into imperative native DOM operations. There is no
virtual DOM and no diffing — every component becomes a standard Custom Element, and
state changes update only the exact DOM node bound to them.

## Why OTF Web

- **Zero-VDOM** — the compiler emits the precise `createElement` and update calls your
  view needs. No reconciliation loop at runtime.
- **Native components** — every component is a real `HTMLElement`. It works in any
  page, with or without a framework.
- **Fine-grained signals** — `$state`, `$derived`, and `$effect` macros wire
  reactivity at compile time, so there is no manual `.value`.
- **Fullstack** — file-based routing, layouts, route guards, and static generation
  are built in.

## A first component

```jsx
export default function Counter() {
  let count = $state(0);

  return <button onclick={() => count++}>Clicked {count} times</button>;
}
```

`count` is a signal. Reassigning it updates only the text node it feeds — nothing else
re-runs.

That button is the snippet above, compiled and running — click it.

<Callout type="info" title="No virtual tree to reconcile">
  The compiled output builds the DOM directly and is interactive immediately. With SSR
  or SSG, first paint adopts the server-rendered nodes in place instead of re-rendering
  them.
</Callout>
