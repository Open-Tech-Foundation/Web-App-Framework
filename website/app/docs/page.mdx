# Introduction

OTF Web compiles JSX directly into imperative native DOM operations. There is no virtual
DOM tree. Reusable components compile to Custom Elements; route pages and layouts
compile to factories. State changes run the dependent DOM bindings.

## Why OTF Web

- **No virtual DOM** — the compiler emits exactly the DOM calls a view requires and binds
  each update to the node it affects. Keyed lists still reconcile their items when
  the list changes.
- **Standards-based components** — every component is a real `HTMLElement`, usable in any
  page, with or without a framework.
- **Fine-grained reactivity** — the `$state`, `$derived`, and `$effect` macros wire
  bindings at compile time. Signals track dependencies when those bindings run,
  so component code reads and writes state without `.value`.
- **Client and server building blocks** — file-based routing and layouts,
  [middleware](/docs/routing/middleware) and [API routes](/docs/routing/api-routes),
  [route loaders](/docs/data-fetching) and [cookies](/docs/routing/cookies), client-side
  [route guards](/docs/routing/route-guards), plus
  [static generation](/docs/deployment/static-generation),
  [server rendering](/docs/deployment/server), and
  [hydration](/docs/deployment/hydration). Server features require an app-owned
  server entry; a browser build alone does not start one.

## A first component

```jsx
export default function Counter() {
  let count = $state(0);

  return <button onclick={() => count++}>Clicked {count} times</button>;
}
```

`count` is a signal. Reassigning it updates only the text node it feeds; nothing else
re-runs.
