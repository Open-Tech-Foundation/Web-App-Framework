# Configuration

An OTF Web project is configured by a single **`otfw.config.js`** at the project root.
It is read by the toolchain (`@opentf/web-cli`) at build and dev time, and by the
themed UI (`@opentf/web-docs`) at runtime.

```js
// otfw.config.js
import { defineDocsConfig } from "@opentf/web-docs/config";

export default defineDocsConfig({
  site: { url: "https://example.com" },
  docs: { title: "My Project", dir: "docs" /* … */ },
  blog: { dir: "blog" },
});
```

`defineDocsConfig` is an identity helper — it returns the object unchanged but gives
your editor full type hints.

<Callout type="info" title="One file, three consumers">
  The CLI uses it to wire build plugins (nav, posts, search, RSS, last-updated); the
  `Navbar`/`DocsLayout` components read `docs` at runtime; and the SSG step reads
  `site.url` for canonical URLs and the sitemap.
</Callout>

## Top-level keys

| Key | Purpose |
| --- | --- |
| `site` | Canonical origin — `{ url }`. Drives absolute canonicals, the sitemap, and the blog RSS feed. |
| `docs` | The documentation section (sidebar, navbar, search). |
| `blog` | An optional blog section (post list, banners, RSS). |

## `site`

```js
site: { url: "https://example.com" }
```

Required for absolute URLs. Omit it (or pass `--base-url` at build) and canonicals stay
relative and the sitemap/RSS are skipped.

## `docs`

The main documentation section. Common fields:

| Field | Type | Notes |
| --- | --- | --- |
| `title` | string | Product name in the navbar. |
| `version` | string | Version badge (e.g. `"v0.4.0"`). |
| `logo` | string | Navbar logo URL. |
| `github` | string | GitHub URL (navbar icon). |
| `repoUrl` | string | Source repo — enables per-page "Edit this page" links. |
| `dir` | string | Content folder under `app/` (default `"docs"`). |
| `nav` | array | Top navbar links: `{ label, href, icon?, external? }`. |
| `footer` | object | `{ text, links }`. |
| `search` | object | `{ provider: "pagefind" }` to enable static search. |
| `lastUpdated` | boolean | Show a "Last updated" line per page (git/frontmatter). |

See [Packages → web-docs → Configuration](/docs/packages/web-docs/configuration) for the
exhaustive field reference and per-folder `_meta.js` ordering.

## Multiple sections

A section like an [API reference](/api) is just **another folder with a `DocsLayout`** —
no config. Any top-level folder under `app/` that has a layout rendering `DocsLayout`
becomes its own section with its own generated sidebar, breadcrumbs, prev/next, and
(with `lastUpdated`) the "Last updated" / "Edit this page" line — the same traits as the
main docs.

```jsx app/api/layout.jsx
import { DocsLayout } from "@opentf/web-docs";
import config from "../../otfw.config.js";

export default function (props) {
  return (
    <DocsLayout config={config.docs} frame={false}>
      {props.children}
    </DocsLayout>
  );
}
```

That's the whole thing — the same layout as `app/docs/layout.jsx`. `DocsLayout` reads the
generated nav and scopes it to the current route, so `app/api/**` shows the `/api` sidebar
(ordered by each folder's `_meta.js`). Add a third section by adding a folder and a copy
of this file.

## `blog`

Turns on the blog generator (post list, banners, reading time, RSS). See
[Packages → web-docs → Blog](/docs/packages/web-docs/blog).

```js
blog: { dir: "blog", title: "My Blog", lastUpdated: true }
```

<Callout type="info" title="Framework vs. theme config">
  `otfw.config.js` is the project config. The `docs`/`api`/`blog` blocks are interpreted
  by `@opentf/web-docs`; a non-docs app can use just `site` and the CLI still builds it.
</Callout>
