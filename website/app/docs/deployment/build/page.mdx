# Production Build

`otfw build` compiles every route and component (JSX/MDX → native DOM), bundles the
result, and writes a deployable site to `dist/`.

```bash
bun run build
# → otfw build
```

## What it produces

```
dist/
  index.html          the app shell, with the hashed bundle injected
  assets/
    bundle-<hash>.js   the entry bundle (code-split per route)
    <chunk>-<hash>.js  lazily-loaded route chunks
    <name>-<hash>.css  compiled stylesheets
```

Routes are code-split: visiting a page loads only its chunk. Filenames are content-
hashed, so they can be cached forever.

## Single-page output

A plain build emits one `index.html`; the client bundle renders every route. Configure
your host to serve `index.html` for unknown paths so deep links resolve:

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

<Callout type="tip" title="Pre-render for SEO">
  Add `--ssg` to also emit a static `.html` for every route — see
  [Static Generation](/docs/deployment/static-generation). Crawlers then get full markup
  without running your JS.
</Callout>

## Base URL

Set `site.url` in `otfw.config.js` so the build can emit absolute canonical URLs, a
sitemap, and (when a blog is configured) RSS/Atom feeds:

```js
export default defineDocsConfig({
  site: { url: "https://example.com" },
});
```

You can override it at build time with `--base-url=https://example.com`.

## Previewing locally

`dist/` is plain static files — serve it with any static server to smoke-test the
production output before deploying:

```bash
bunx serve dist
```
